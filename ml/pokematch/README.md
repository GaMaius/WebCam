# PokéMatch — 데이터 준비 / 모델 파이프라인

"닮은 포켓몬 찾기" 앱에 필요한 **웹 자산**을 Colab에서 생성하는 워크플로우.

## 접근

분류 학습이 아니라 **임베딩 최근접 + 인기편향 제거 z-score 재랭킹**:

1. 사전학습 경량 인코더(MobileCLIP2-S0, 가중치 동결)로 포켓몬 종별 대표 벡터(갤러리) 미리 계산
2. 웹에서 얼굴 crop을 **동일 인코더**로 임베딩(onnxruntime-web)
3. 원시 코사인이 아니라 **z-score 재랭킹**: `z = (코사인 − μ_p) / σ_p` → 상위 5개

사람 얼굴↔포켓몬의 정답 라벨이 없으므로 지도학습 분류는 성립하지 않는다(데이터셋 설명도
분류 이미지를 "임베딩/유사도 비교용"으로 규정).

**⚠️ z-score 재랭킹이 핵심.** 원시 코사인으로는 '파라스처럼 모든 얼굴과 가까운' 포켓몬이
누구를 넣어도 1등이 되어 결과가 사실상 상수가 된다. 일반 얼굴 집단(LFW) 대비 각 포켓몬의
평균 유사도 μ_p·표준편차 σ_p로 표준화해 "그 사람에게 유별나게 가까운" 포켓몬을 뽑아야
사람마다 개성 있는 결과가 나온다. (검증: 카리나→가디안·디안시(우아한 페어리), 남성→갈레이드·
메디컴(인간형 파이터).) μ_p·σ_p는 노트북 **7-B 셀**에서 gallery.json에 저장.

전처리 상수(5번 셀): **256 리사이즈·센터크롭, 정규화 없음([0,1] 입력), RGB.**

## 실행

[`prepare_pokematch.ipynb`](prepare_pokematch.ipynb) 를 Colab(GPU)에서 위에서부터 실행.

생성물:

| 파일 | 용도 | 배치 |
|---|---|---|
| `pokemon_encoder.int8.onnx` | 브라우저 임베딩 | 웹 `/public/models/` (작으면) 또는 B2 |
| `gallery.bin` + `gallery.json` | 1069종 프로토타입 벡터(int8)+메타 | 웹 `/public/pokemon/` |
| `pokedex.json` | 도감번호·한글명·영문명·타입 | 웹 `/public/pokemon/` |
| `pokedex_webp/*.webp` | 결과용 대표 이미지 | **B2 `pokedex/`** |

## 주의

- **전처리 일치**: 노트북 5번 셀이 출력하는 resize/crop/mean/std/IMG_SIZE 를 웹 얼굴 전처리에
  픽셀 단위로 동일하게 옮겨야 한다(최대 버그 지점).
- **인코더 동일성**: 갤러리와 브라우저가 반드시 같은 인코더/정규화를 써야 한다.
- 데이터에는 메가·폼·패러독스 포켓몬이 포함(슬러그 언더스코어). 도감번호/한글명은 PokéAPI
  best-effort 보강이며 일부 미확인은 9번 셀의 예외 매핑으로 보완한다.
- 데이터셋은 리포에 포함하지 않는다(로컬/Kaggle/Drive에서만 사용).
